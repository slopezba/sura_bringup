# sura_bringup

`sura_bringup` is the entry point used to start a complete SURA robot.

It does not contain the robot model, controllers, sensors or localization
logic. Instead, it reads the robot bringup configuration and launches the
packages that make up the system with the correct namespace and configuration
files.

## Main Launch

```bash
ros2 launch sura_bringup sura_bringup.launch.py \
  robot_namespace:=<robot_namespace>
```

The value of `robot_namespace` is important because it is used to find the robot
description package:

```text
<robot_namespace>_description/config/bringup_description.yaml
```

For example, if the namespace is `<robot_namespace>`, the robot description
package must provide:

```text
<robot_namespace>_description
└── config/
    └── bringup_description.yaml
```

The robot-specific configuration is read from that file. The namespace must
also match:

- `robot.name` in `bringup_description.yaml`;
- the robot name generated by the xacro file.

## Launch Files

### `sura_bringup.launch.py`

This is the normal launch file for starting the robot.

```bash
ros2 launch sura_bringup sura_bringup.launch.py \
  robot_namespace:=<robot_namespace>
```

It reads:

```text
<robot_namespace>_description/config/bringup_description.yaml
```

and starts:

| What it starts | Notes |
| --- | --- |
| Robot description launch | From the robot description package. |
| ROS 2 Control launch | Through `sura_controllers.launch.py`. |
| Hardware interface plugins | Loaded by `ros2_control` from the robot description and controller YAML. |
| IMU filtering | Through `sura_imu/launch/imu.launch.py`. |
| Localization | The launch selected by `localization.launch_package` and `localization.launch_file`. |
| Navigator | Through `sura_navigator/launch/navigator.launch.py`. |
| Diagnostics | Through `sura_diagnostics/launch/diagnostics.launch.py`. |
| Thruster-force publisher | From `sura_hardware_interface`. |

Camera bringup exists in the code but is currently commented out in this launch.

### `sura_controllers.launch.py`

This launch is called internally by `sura_bringup.launch.py`.

The user normally does not execute it directly. The robot must be linked to a
description package with the same base name as the namespace:

```text
<robot_namespace>_description
```

From that description, this launch reads the robot xacro and the `ros2_control`
YAML. Then it starts `ros2_control_node` and spawns the configured broadcasters
and controllers.

The robot xacro must define a valid robot `family`, because that decides which
controller groups are used:

| Family | Controller groups |
| --- | --- |
| `underwater` | `common_controllers`, `auv_controllers` |
| `surface` | `common_controllers`, `usv_controllers` |

### `sura_perception.launch.py`

This launch starts one camera through `sura_cameras`.

```bash
ros2 launch sura_bringup sura_perception.launch.py \
  robot_namespace:=<robot_namespace> \
  camera_name:=down_camera \
  camera_config_dir:=<camera_config_dir> \
  environment:=real \
  aruco:=true
```

It includes:

```text
sura_cameras/launch/single_camera.launch.py
```

If `robot_namespace` is provided, the camera is launched inside that namespace.

### `sura_gcs.launch.py`

This launch starts a ground-control-station view.

```bash
ros2 launch sura_bringup sura_gcs.launch.py \
  robot_namespace:=<robot_namespace> \
  teleop_enabled:=true
```

It starts:

| What it starts | Notes |
| --- | --- |
| RViz | Using `config/sura.rviz`. |
| Teleop | Through `sura_teleop/launch/teleop.launch.py`, when `teleop_enabled:=true`. |

It also loads robot description and MoveIt configuration for visualization.
For a robot different from the default one, pass the matching
`robot_description_package`, `robot_description_file`,
`robot_description_semantic_package`, `robot_description_semantic_file` and
`xacro_arguments`.

This launch is not required for the main robot bringup.

## Quick Checks

Check that the robot description is being published:

```bash
ros2 topic echo /<robot_namespace>/robot_description --once
```

Check the controller manager:

```bash
ros2 control list_controllers -c /<robot_namespace>/controller/controller_manager
```

Check the navigator output:

```bash
ros2 topic echo /<robot_namespace>/navigator/navigation --once
```

Check diagnostics:

```bash
ros2 topic echo /diagnostics --once
```
